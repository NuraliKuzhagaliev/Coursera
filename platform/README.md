# Коммерческая платформа Coursera Queue

Лицензируемая сборка имеет версию 2.0.0. Клиент Manifest V3 содержит React-интерфейс аккаунта, TypeScript-модуль авторизации и локальные адаптеры Coursera и ChatGPT. Fastify API на Render проверяет JWT, сессию, лицензию, версию и квоту. Формирование запросов модели, проверка ответов и вычисление итогового статуса курса выполняются сервером.

## Установка клиента

1. Установите зависимости командой `npm ci` с Node.js 22.20+.
2. Заполните закрытый локальный `.env` по образцу `.env.example`.
3. Выполните `npm run build:commercial`.
4. Папка `dist/extension` готова для загрузки через `chrome://extensions`. В установочный ZIP включается только эта папка. Серверные исходники, миграции и `.env` поставляются владельцу платформы отдельно.
5. Зарегистрируйте аккаунт расширения, подтвердите почту и войдите. Администратор должен выдать лицензию или пользователь должен оплатить настроенный тариф.

История очереди хранится в профиле Chrome. Для сохранения существующей истории обновляйте уже установленное расширение в той же подключённой папке и используйте ↻. Установка из другой папки может создать новый идентификатор расширения.

## Сервер и база

В текущей конфигурации используются бесплатные сервисы Render и закрытая схема `coursera_queue` внутри существующего проекта Supabase SlotPilot. Supabase Auth общий для этого проекта. Отдельные лицензии, роли и сессии приложения проверяются собственным сервером. Таблицы проекта SlotPilot находятся в другой схеме.

Миграции находятся в `supabase/migrations`. Все таблицы лицензирования имеют RLS и закрыты для ролей `anon` и `authenticated`. Публичный RPC `cq_dispatch` проверяет отдельный случайный серверный ключ до чтения данных. В базе хранится только SHA-256 ключа. Клиент получает только publishable key Supabase. Серверный ключ имеет полномочия только в этом приложении.

Если до миграции учёта нескольких подписок уже существуют Stripe-лицензии, владелец сначала добавляет `subscription_id` командой `ADD COLUMN IF NOT EXISTS` и заполняет его проверенным Stripe subscription ID для каждой существующей записи. При неизвестных ID миграция остановится с ошибкой и сохранит доступ. После сопоставления её можно повторить. Миграция сохраняет оплаченные лицензии.

Для нового развёртывания сгенерируйте `CQ_SERVER_KEY` из 32 криптографически случайных байтов, сохраните его только в окружении API и закрытом локальном `.env`. После применения миграций владелец базы устанавливает SHA-256 ключа в `coursera_queue.config.backend_key_hash`. Публичный клиент не должен получать исходный ключ или права административных ролей базы.

В Render API требуются `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `CQ_SERVER_KEY`, `ADMIN_ORIGIN`. Кабинету нужен `NEXT_PUBLIC_API_ORIGIN`. Для сборки расширения нужен `BUILD_API_ORIGIN`. `render.yaml` описывает оба бесплатных сервиса.

Команда сборки API — `npm ci && node platform/build.mjs --server-only`. Запуск — `npm run start:api`. Кабинет собирается `npm ci && npm run build:admin` и запускается `npm run start:admin -- --hostname 0.0.0.0 --port $PORT`.

В Supabase Auth включите подтверждение почты и добавьте адрес кабинета с `/**` в разрешённые Redirect URLs. Общий Site URL оставьте SlotPilot: регистрация и восстановление в этом приложении передают собственный адрес возврата. Если используются собственные почтовые шаблоны, ссылки должны учитывать Redirect URL, а не вести всегда на Site URL. Восстановление пароля выполняется на сайте кабинета с PKCE. Для коммерческой рассылки настройте собственный SMTP в Supabase. При общей Auth-конфигурации изменения почтовых шаблонов и настроек действуют на весь проект.

## Первый администратор

1. Зарегистрируйте отдельный административный аккаунт через кабинет и подтвердите почту.
2. Выполните обычный вход, чтобы появилась строка `coursera_queue.accounts`.
3. Владелец Supabase назначает этому подтверждённому `user_id` роль через SQL. Пример с заменяемым UUID приведён ниже.

```sql
update coursera_queue.accounts
set role = 'admin'
where user_id = '00000000-0000-0000-0000-000000000000';
```

Имя и почта Coursera используются для отображения. Права администратора и лицензия определяются `user_id` Supabase и серверными таблицами. Скрипт чтения Coursera открывает `/account-settings`, читает видимые поля Full name и Email address и закрывает созданную вкладку.

Администратор может выдавать и продлевать лицензии, отзывать их, блокировать пользователей, завершать сессии, включать ограничение устройства, менять тарифы, квоты и версию клиента. В кабинете показываются платежи, расход квот, журнал действий и последние ошибки процесса API. Для архива ошибок используйте логи Render. Кнопка резервной копии выгружает данные кабинета, без паролей и токенов сессий.

## Сессии и отзыв

Каждый новый вход создаёт одну серверную сессию приложения и атомарно отзывает предыдущую. Старый JWT сам по себе не восстанавливает отозванную сессию. Привязка устройства использует случайный идентификатор установки. Такой идентификатор можно подделать при полном контроле клиентской системы.

При запуске, обновлении, перезапуске браузера и восстановлении сети выполняется повторная проверка. Во время работы проверка повторяется каждые две минуты. Перед действиями открытия, заполнения и отправки проверка выполняется через защищённый API. Каждая серверная операция заново сверяет строку Auth-сессии, сессию приложения и права. Сетевой сбой закрывает новый доступ.

Один аккаунт лицензии поддерживает одну активную сессию. Для отдельных операторов и административного кабинета используйте отдельные аккаунты. Если под одной лицензией войти в другой профиль, предыдущий профиль остановится.

## Stripe

Сейчас Stripe выключен по решению владельца. Код поддерживает тестовый режим. Для включения в окружении API задайте `STRIPE_SECRET_KEY=sk_test_...` и `STRIPE_WEBHOOK_SECRET=whsec_...`. Эти значения вводятся в закрытых настройках Render и не отправляются в чат или клиентскую сборку.

Создайте в Stripe тестовые recurring Prices для Standard и Pro. Укажите их ID, цену в минимальных единицах валюты и валюту в админке. Начальные цены оставлены незаданными. Кнопка оплаты станет доступна после настройки тарифа.

Webhook должен отправляться на `/v1/billing/webhook` API. Подпишитесь на `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.paid`, `invoice.payment_failed`.

Сервер проверяет подпись сырых байтов webhook, тестовый режим, клиента Stripe, цену и оплаченный актуальный статус подписки. Событие обрабатывается идемпотентно. Для повторных и запоздавших событий сервер повторно читает текущую подписку Stripe. Короткая блокировка с ограниченным сроком и проверкой владельца защищает от конкурирующих обработчиков.

## Проверки

```powershell
npm run typecheck:platform
npm run test:platform
npm run build:commercial
npm run build:admin
node platform/tests/browser.mjs
```

Тесты используют настоящий PostgreSQL-движок PGlite, локальный JWKS и настоящую криптографическую проверку JWT. Проверяются поддельные JWT и email, клиентская подмена роли и лицензии, конкурентные входы, отзыв сессий, удаление Auth-сессии, блокировка и истечение лицензии, привязка устройства, RLS, квоты и повторные запросы, версия клиента, подпись и повторная доставка Stripe webhook.

Тестовый Stripe-адаптер не проводит реальные платежи. Проверка реальной регистрации, почтовых писем и оплаты тестовой картой требует настроенного Supabase Auth, SMTP и ключей тестового аккаунта Stripe.

## Границы защиты

Клиент минифицирован без production source maps и динамического исполнения удалённого JavaScript. Сервер выдаёт данные, результаты обработки и ограниченные решения. Клиентская логика работы с DOM остаётся в расширении.

Удаление экрана входа не открывает защищённый API. Пользователь с полным контролем компьютера может изучать локальные действия, подделывать идентификаторы установки и самостоятельно реализовать похожий продукт. Ранее опубликованный исходный код и старые локальные версии тоже доступны их получателям. Коммерческая сборка не может удалить эти копии.

Бесплатные сервисы могут засыпать и иметь ограничения базы и почты. При недоступности API расширение приостанавливается. Ежедневные управляемые резервные копии и гарантированная доступность зависят от тарифов инфраструктуры. Экспорт кабинета и миграции предназначены для ручного резервного копирования приложения.

Фактически выполненные проверки и оставшиеся ограничения перечислены в [VERIFICATION.md](VERIFICATION.md).
