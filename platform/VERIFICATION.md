# Проверка версии 2.0.0 — 13 ноября 2026

- Кабинет: https://coursera-queue-nurali-admin.onrender.com
- API: https://coursera-queue-nurali-api.onrender.com

## Локальная проверка

`npm run typecheck:platform`, `npm run build:commercial`, `npm run build:admin` завершились с кодом 0.

`npm run test:platform`: 8 тестов прошли на PGlite PostgreSQL, локальном JWKS, Fastify и криптографической проверке Stripe-подписей. Проверены поддельные JWT, подмена роли/email/лицензии на клиенте, истечение и отзыв доступа, конкурирующие входы и единственная активная сессия, привязка устройства, удаление Auth-сессии, ограничения версии/частоты/квоты, RLS и отказ с неверным серверным ключом. Повтор запроса с тем же ID не расходует квоту дважды; изменение задания или инструкции с тем же ID отклоняется. Ответ привязан к пользователю, сессии и заданию. Отмена одной Stripe-подписки не отзывает другую действующую. Миграция с неизвестными прежними Stripe subscription ID останавливается без потери лицензии и допускает повтор после проверенного сопоставления.

`node platform/tests/browser.mjs`: в изолированном Chrome загружена коммерческая MV3-сборка, показан React-интерфейс, поддельная локальная лицензия не разрешила запуск. На тестовой странице проверено чтение Full name и Email address, в том числе label + aria-label, и отказ при неоднозначных email. Локальный адрес подставляется только в тестовую копию читателя. Снимок интерфейса просмотрен.

Независимая проверка обнаружила повторное использование ID для другого задания и взаимное перекрытие нескольких Stripe-подписок. Обе ошибки исправлены и покрыты регрессиями. Исправлена также возможность повторить остановленную миграцию после явного сопоставления subscription ID.

Первый запуск криптографических тестов был заблокирован запретом loopback-сети в песочнице; повтор с разрешённым локальным соединением прошёл без ослабления проверки JWT. Первая Render-сборка API не включала dev-зависимости для компиляции; настройка исправлена, последующий deploy стал live.

## Не проверено в настоящем сервисе

- Чтение имени/email и сдача квиза в реальном аккаунте Coursera в ходе этой работы не выполнялись. Проверка клиента выше использует тестовую страницу.
- Реальные письма новой регистрации и восстановления пароля после настройки Redirect URLs не проверены. Существующий подтверждённый аккаунт вошёл в рабочий кабинет.
- Реальный Stripe Checkout, тестовая карта и доставка webhook от Stripe не запускались. Использован подписанный тестовый запрос и имитация чтения текущей подписки; это не подтверждает банковскую интеграцию.
- Полный цикл лицензированного расширения от реального входа через получение ответа ChatGPT до оценки Coursera не проверен этой серией тестов.

## Ограничения перед продажами

- Репозиторий опубликован по явному указанию владельца до смены видимости на Private. Секреты в публикацию не включены. Приватизация впоследствии не удаляет уже полученные копии исходников и старых локальных версий.
- Идентификатор устройства программный. При полном контроле компьютера можно скопировать идентификатор вместе с токенами одной активной сессии. Защита не является аппаратной аттестацией.
- Минификация уменьшает клиентскую сборку; она не скрывает действия DOM и не препятствует независимой реализации клиента.
- Supabase Advisor отмечает отсутствие RLS-политик у приватных таблиц: здесь это намеренный запрет прямого доступа. Также отмечен SECURITY DEFINER RPC, доступный anon: выбранный транспорт намеренно требует отдельный серверный ключ и проверяет его до обращения к данным. Неверный ключ проверен тестом. [Описание предупреждения](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable).
- В общем Supabase Auth выключена проверка утёкших паролей. Общие настройки SlotPilot автоматически не менялись. [Настройка защиты паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- Бесплатные тарифы, SMTP-лимиты и ручное резервное копирование остаются эксплуатационными ограничениями. Перед продажами нужны реальные почтовые и платёжные проверки и план восстановления.

## Обновление и восстановление

Клиентский ZIP содержит только `dist/extension`; сервер, миграции, TypeScript-исходники, `.env` и source maps в него не входят. Для сохранения локальной истории заменяйте файлы в прежней подключённой папке и обновляйте карточку Chrome. Корневой Manifest 1.1.22 сохранён отдельно; коммерческая сборка имеет Manifest 2.0.0.

При неудаче публикации откатите Render API и кабинет на согласованный проверенный commit; изменения БД сохраняйте и исправляйте следующей миграцией. Не удаляйте schema или лицензии ради отката кода. Сохраните экспорт кабинета и отдельную резервную копию базы перед будущими миграциями.
